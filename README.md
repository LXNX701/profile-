# MOONX7 Profile\n\nPublic Free Fire profile lookup powered by a serverless Node/Express API and Supabase persistence.\n\n## Included\n- UID + region lookup\n- Account information\n- BR / CS ranks and ranking points\n- Player statistics\n- Guild information when a guild ID is available\n- Wishlist items\n- Craftland profile data\n- Craftland map endpoint\n- Persistent Supabase cache with stale-cache fallback\n- Search logging with hashed IP addresses\n- Responsive Liquid Glass-style web UI\n- Vercel and Netlify deployment files\n- API endpoints for integrations\n\n## Supported provider regions\nThe upstream provider documents these primary regions: IND, BR, SG, RU, ID, TW, US, VN, TH, ME, PK, CIS, BD. The UI also keeps aliases such as NA, LATAM, SAC, EU, EUROPE and MY so the region registry can be extended without changing the frontend.\n\nThe actual data available for a player depends on the upstream provider and Free Fire region/service. This project does not claim that every field exists for every account.\n\n## API\n- GET /api/health\n- GET /api/regions\n- GET /api/profile?uid=UID&region=REGION\n- GET /api/account?uid=UID&region=REGION\n- GET /api/playerstats?uid=UID&region=REGION\n- GET /api/wishlistitems?uid=UID&region=REGION\n- GET /api/craftlandProfile?uid=UID&region=REGION\n- GET /api/craftlandInfo?map_code=CODE&region=REGION\n- GET /api/guild?guildID=ID&region=REGION\n\n## Supabase\nThe application uses public.profile_cache and public.profile_searches.\nThe server uses SUPABASE_SECRET_KEY (preferred) or the legacy SUPABASE_SERVICE_ROLE_KEY. Never put either secret in frontend code or commit it to GitHub.\n\n## Deploy on Vercel\n1. Import this repository into Vercel.\n2. Add the environment variables from .env.example.\n3. Deploy.\n4. Open /api/health.\n5. Open the site and test a UID.\n\nNo build command is required for the static frontend + /api function.\n\n## Deploy on Netlify\n1. Import this repository into Netlify.\n2. Add the same environment variables.\n3. Deploy.\n4. Open /api/health.\n5. Test a UID.\n\nnetlify.toml routes /api/* to the serverless function.\n\n## Notes\nThe public provider currently used by default is documented by the open-source Free Fire API project and may experience rate limits, downtime, or changes. Set FF_UPSTREAM to another compatible provider later without changing the UI/API contract.\n\n## Security\n- Server-side Supabase secret only.\n- RLS is enabled on cache/search tables.\n- Search IPs are hashed before storage.\n- UID and identifier validation is applied at the API boundary.\n- Provider requests have a timeout.\n- Stale Supabase cache can be served when the provider is temporarily unavailable.
